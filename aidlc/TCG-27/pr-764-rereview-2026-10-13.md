## CODE — original finding and re-review

1. **Original P1, resolved by source inspection:** `notifications-ws-auth.service.ts` now compares the token's session version with the current account version, interpreting legacy omission as zero. The gateway checks admission, subscription and each created/read/unread delivery. Stale sessions disconnect before further payload delivery. All three production notification-service emit callers await the now-asynchronous gateway methods. Enumeration failures never fall back to an unchecked broadcast.

2. **[P2] [INFERRED] Expiry regression found in `65e6aa238`, corrected locally:** the original socket handshake retains its access token even after HTTP refresh changes the browser cookies. Verifying that original token's expiry before every delivery disconnected a healthy current-version socket on its next event after expiry. The web hook has no server-disconnect recovery handler and depends on user ID/query client; installed Socket.IO client handling destroys reconnection subscriptions on a server disconnect. Consequently `reconnection: true` did not recover live notifications.

   Reasoned from `notifications.gateway.ts:140–142` in `65e6aa238`, `notifications-ws-auth.service.ts:30`, `apps/web/src/lib/base-api.ts:205–214`, `apps/web/src/features/notifications/hooks/use-notification-socket.ts:27–64`, and installed Socket.IO client's `ondisconnect`/`destroy` implementation. No runtime reproduction was executed.

   **Correction:** the existing `authenticateHandshake` accepts an established-connection mode, default false. New connection admission still enforces JWT expiry. Only authenticated subscription and user-room delivery use established mode; it retains JWT signature validation and current account status, identity/tenant and session-version checks while preserving the pre-existing lifetime of an established transport. HTTP credential renewal therefore does not destroy a valid notification connection.

   **Refutation/security check:** this does not permit opening a new connection with an expired token: `handleConnection` uses the strict default. Established subscription requires server-controlled cached user/tenant IDs; delivery enumerates server-controlled user-room membership. Both also compare the verified identity with the expected user and tenant. An expired prior-version token still fails the version comparison, and an invalid signature still fails cryptographic validation. Existing sockets may stay idle after reset, but cannot deliver further account data without revalidation. Reset concurrent with an already-authenticated operation retains the existing HTTP-style in-flight boundary; later operations check the new version.

No further concrete defect survived the final independent analyst pass. Remote head `65e6aa238` retains item 2 until the local correction is committed and pushed.
