# UAT Final Doc — the UAT request register

**What this is.** A verbatim transcription of the Confluence page *UAT Final Doc*
(page `175865858`), the register Fouzan Shakil assembled on 2026-09-18 from the six UAT
session sheets and checked row by row against `origin/main` at `f800a3972`. 252 rows over
two tables — 100 done, 152 not done.

**What it is not.** It is **a record of requests and their build status, never a source for
a spec.** A UAT row is what somebody asked for in a session; nothing on this page was
adjudicated as product intent. Where a row asserts how the product must behave, that
assertion is unsourced until a decision note or a module `gaps.md` entry carries it. See
[uat/INDEX.md](INDEX.md).

The page's own caveats — the unverified UAT 6 rows, the untraceable rows, the two genuinely
unresolved items — are preserved below in its own words.

## How to use this page

Two tables: what is **done** and what is **not done**. Every row carries the same five columns.

**Status** is what we found — click the lozenge to change it as work lands. **Item** is the original request in plain words. **Src** links to the exact point on the session sheet it came from; rows with no Src could not be traced to any of the five sessions. **Comments** is the finding: what the code actually does and which file proves it. **Owner** is blank on purpose — put your name there to claim a row.

A row is only **DONE** if the thing complained about in UAT no longer happens. Anything half-built sits in **NOT DONE** with the remaining gap spelled out in Comments — because a half-fix gets re-reported at the next session just like no fix at all.

## Read this first

**Push notifications do not work on any phone.** There is no Firebase config file in the app at all, so Android never gets a token and iOS sends a token the server rejects and deletes. The server half is complete and correct — only the app's native config is missing.

**Allocations can still be removed after the time has passed.** The delete check looks at payroll locks and whether tickets were sent — it never looks at the clock.

**The Pre-Inspection checklist still pre-ticks every item.** The fix exists, but a build setting turns the autofill back on in every build we ship, including production.

**Nine items widely believed outstanding are already built** — anyone working from an older list will rebuild finished work. They are in the Done table with the evidence.

## How this was checked

**Basis:** `origin/main` at `f800a3972` plus the two commits on `fix/remove-chrome-suggestions`. Every claim was checked by reading the implementing source file and, where relevant, finding the commit that shipped it. Findings that cannot be settled from source alone — live email rendering, push delivery on a real handset, app crashes — are labelled as such rather than guessed.

**Coverage:** verified line by line — all 201 bullets across session sheets 1–5 were mapped to a row individually, and none is missing. The 38 points from session 6 were then added the same way and checked against the existing rows for duplicates — six overlap an earlier row and are cross-referenced rather than silently duplicated. Nine requests appear on more than one sheet and share a single row, which the Comments cell names; UAT 4 #31 deliberately keeps two rows because its two readings give opposite answers. This is why the per-session row counts sit below the raw bullet counts.

**Statuses:** every status from sessions 1–5 was verified against source; **the 38 UAT 6 rows were not** — they are recorded as NOT DONE on the basis that the session listed outstanding work. The 35 items that could not be settled from code were put to the team on 9/18/2026 and resolved one at a time; each carries the decision in its Comments cell. **Two of them remain genuinely unresolved** — UAT 4 #31 and the evidence-standard question — and are carried as Not done so the page needs only two statuses.

**Rows with no Src** could not be traced to any of the five sessions. Nine of them are bugs found during this audit; the rest arrived from a list whose origin is unrecorded. They are kept so the work is not lost, but their provenance should be confirmed before anyone acts on them.

**Confidence:** the highest-impact findings — the missing push config, the allocation time check, and the rate example's true location — were each verified a second time by hand rather than accepted from a single pass. Two findings were corrected mid-audit when a second look disagreed with the first; both corrections are reflected above.
